# DostupVPN Android

Небольшое приложение: вход по токену, подключение к VLESS + Reality.

## Как устроено

- `net/` — API сервера (`/v1/session/start`, `heartbeat`, `stop`), вход по токену.
- `vpn/XrayConfig.kt` — собирает конфиг Xray: `tun` inbound → `vless` + Reality outbound + маршрутизация по странам.
- `ui/` — интерфейс (Compose): главный экран по макету, шторки «Подписка» и «Настройки», тема AUTO/светлая/тёмная.
- `diag/` — коды ошибок, журнал событий подключения и отчёт для поддержки.
- `vpn/DostupVpnService.kt` — поднимает системный TUN и передаёт его ядру **Xray-core**
  (библиотека [2dust/AndroidLibXrayLite](https://github.com/2dust/AndroidLibXrayLite), та же, что в v2rayNG).
  Собственный пакет исключён из VPN, поэтому сокеты ядра и запросы к API идут напрямую.
- Каждые `heartbeatSec` секунд отправляется heartbeat; при `410` сессия создаётся заново.

## Сборка

Workflow `.github/workflows/main.yml` скачивает готовый `libv2ray.aar` (версия в `LIBV2RAY_VERSION`),
оставляет в нём только arm64 и убирает полные geo-базы (свои урезанные лежат в `app/src/main/assets/geo`), затем собирает debug-APK
(артефакт `DostupVPN-debug-apk`).

## Диагностика (нужна debug-сборка и adb)

```powershell
adb exec-out run-as com.dostupvpn.app cat files/xray.log            # лог ядра Xray
adb exec-out run-as com.dostupvpn.app cat files/session-debug.txt   # параметры сессии (без секретов целиком)
adb exec-out run-as com.dostupvpn.app cat files/java-crash.log      # Java-падение
adb logcat -v time | Select-String "DostupVpnService|GoLog|AndroidRuntime"
```

## Подпись (чтобы приложение обновлялось поверх старой версии)

Все сборки должны подписываться одним и тем же ключом. Ключ хранится в секретах репозитория
(Settings → Secrets and variables → Actions → вкладка Secrets → **Repository secrets** → New repository secret;
секреты из раздела *Environment secrets* workflow не видит):

| Секрет | Значение |
|---|---|
| `SIGNING_KEYSTORE_BASE64` | файл `.keystore`, закодированный в base64 |
| `SIGNING_STORE_PASSWORD` | пароль хранилища |
| `SIGNING_KEY_ALIAS` | алиас ключа (например `dostupvpn`) |
| `SIGNING_KEY_PASSWORD` | пароль ключа (для PKCS12 совпадает с паролем хранилища) |

Создание ключа (один раз, на своём компьютере):

```powershell
keytool -genkeypair -v -keystore dostupvpn.keystore -alias dostupvpn -keyalg RSA -keysize 2048 -validity 10000
[Convert]::ToBase64String([IO.File]::ReadAllBytes("dostupvpn.keystore")) | Set-Clipboard
```

**Сохраните `dostupvpn.keystore` и пароли в надёжном месте** (менеджер паролей). Потерянный ключ
восстановить нельзя: обновить приложение поверх установленного станет невозможно.
В логе CI шаг «Show signing certificate» печатает SHA-256 сертификата — он должен совпадать между сборками.

## Маршрутизация по странам

Напрямую (мимо VPN) идёт: российские домены (`.ru`, `.su`, `.рф`, списки `geosite:category-ru`,
Яндекс, VK, Сбер, Ozon и др.), российские IP (`geoip:ru`) и локальные сети. Остальное — через VPN.
Порядок правил (первое совпавшее): правила админа «через VPN» → правила админа «напрямую» →
локальные сети → российские домены → российские IP → всё остальное в VPN.

Базы `geoip.dat` / `geosite.dat` вшиты в APK и урезаны до российских списков (≈450 КБ вместо 28 МБ).
Обновить их (например, вместе с новой версией libv2ray):

```bash
unzip -j libv2ray.aar 'assets/geoip.dat' 'assets/geosite.dat' -d /tmp/geo-src
python3 tools/trim_geo.py /tmp/geo-src app/src/main/assets/geo
```

### Правила администратора (без выпуска новой версии приложения)

Файл `/etc/vpn/app_rules.json` на сервере (пример — `docs/app_rules.example.json`) отдаётся через
`GET /v1/rules`. Приложение забирает его при каждом подключении; новые правила действуют со следующего подключения.

- `proxy_domains` / `proxy_ips` — всегда через VPN (перекрывают российские списки: например, заблокированный `.ru`-сайт);
- `direct_domains` / `direct_ips` — всегда напрямую;
- `bypass_apps` — приложения (имена пакетов), которые **вообще не используют VPN** (см. ниже);
- домены: `example.com` (с поддоменами) или `full:host.example.com` (точное имя);
- IP: адрес или CIDR (`203.0.113.0/24`), префикс `/0` запрещён.

**После каждой правки увеличивайте `version`** — сервер отдаёт правила, только если версия новее, чем у приложения.
Некорректные записи приложение молча отбрасывает (чтобы опечатка не ломала запуск у всех пользователей);
`geosite:`, `geoip:`, `regexp:` в этих правилах не поддерживаются.

## Ошибки и обратная связь

При сбое приложение показывает карточку с понятным текстом, **кодом** и кнопкой «Отправить отчёт».
Отчёт (также в «Настройки → Обратная связь») содержит версию приложения и Android, код и детали ошибки,
параметры сессии, события подключения и хвост журнала ядра. Токены, UUID и ключи вычищаются;
из журнала ядра дополнительно убираются IP-адреса и имена узлов (`<ip>`, `<host>`). История посещений не ведётся
(access-лог Xray выключен), поэтому адреса посещённых сайтов в отчёт не попадают.

| Код | Что значит |
|---|---|
| `E-NET` | нет связи с сервером |
| `E-TLS` | не прошла проверка сертификата сервера |
| `E-401` | сессия завершена (слот освобождён в боте) — нужен новый токен |
| `E-402` | подписка не активна |
| `E-404` | токен недействителен или истёк |
| `E-429` | слишком много попыток |
| `E-5xx` | сервер временно недоступен |
| `E-VPN-PERM` / `E-VPN-REVOKED` | нет разрешения на VPN / Android его отозвал |
| `E-CFG` | не удалось собрать настройки подключения |
| `E-CORE` | не запустилось ядро Xray (подробности в отчёте) |
| `E-TIMEOUT` | служба не успела запуститься |
| `E-CRASH` | предыдущий запуск завершился аварийно |

## Уведомление

Пока VPN включён, в шторке есть уведомление с таймером подключения и кнопкой «Отключить».
На Android 13+ приложение запрашивает разрешение на уведомления при первом подключении;
без него уведомление (и кнопка) не показывается, но VPN работает.

## Бета-версия для тестеров

Workflow собирает два файла: **`DostupVPN-beta-N.apk`** (релизная, для тестеров; артефакт `DostupVPN-beta-apk`)
и `DostupVPN-debug-N.apk` (для разработчика, работает `adb run-as`). Обе подписаны одним постоянным ключом,
поэтому новая версия устанавливается **поверх** старой без удаления — ничего не теряется.

Как раздать: скачайте артефакт `DostupVPN-beta-apk` из вкладки Actions, распакуйте и отправьте APK тестеру
(Telegram, почта). Номер сборки `N` растёт сам — по нему видно, какая версия у кого (Настройки → «О приложении»).

Что сказать тестеру:
1. Разрешить установку из этого источника (Android спросит сам).
2. При первом подключении подтвердить запрос на VPN и разрешить уведомления.
3. Нажать «Разрешить» в подсказке про работу в фоне (или Настройки → «Работа в фоне») — иначе ночью Android
   может отключать VPN. На Xiaomi/Huawei/Samsung дополнительно включить автозапуск и снять ограничения батареи в настройках
   телефона для DostupVPN.
4. Если VPN несколько раз подряд не подключается — в карточке ошибки появится «Отправить отчёт»; отчёт также
   можно отправить в Настройках.

Почему R8 (сжатие кода) выключен: выигрыш 2–3 МБ не стоит риска падений, которые нельзя проверить без устройства.
Включить можно после бета-периода.

## Восстановление соединения

Когда телефон долго заблокирован, Android урезает работу приложений, и heartbeat не доходит до сервера; сервер удаляет
конфиг и отвечает `410`. Проснувшись, служба сама создаёт новую сессию: при отсутствии сети не сдаётся, а повторяет
попытки (паузы 5, 10, 15 … до 60 с) и реагирует на возвращение сети мгновенно. Во время восстановления кнопка показывает
«Подключение…» («Восстановление соединения…»), таймер подключения не сбрасывается. Окончательно VPN останавливается
только при `401`/`402` (сессия завершена / подписка не активна).

Отчёт об ошибке предлагается только после **3 неудачных попыток подключения подряд** (`REPORT_MIN_FAILS` в `diag/AppError.kt`)
или после сбоя самого приложения; ошибки, которые пользователь исправляет сам (токен, подписка, лимит, разрешение VPN),
отчёт не предлагают никогда. Из Настроек отчёт можно отправить всегда.

### Приложения вне VPN (`bypass_apps`)

Часть приложений определяет VPN, сравнивая внешний IP, который видят разные сервисы: при делении по странам
российские сервисы видят ваш реальный IP, а зарубежные — IP сервера. Расхождение выдаёт VPN и раскрывает адрес сервера.
Надёжная защита — вообще не пускать такое приложение в VPN: все его запросы, в том числе к зарубежным сервисам
определения IP, идут напрямую и показывают один и тот же реальный адрес.

```json
{ "version": 3, "rules": { "bypass_apps": ["ru.*", "com.vkontakte.*", "com.example.messenger"] } }
```

Запись — точное имя пакета (`com.example.messenger`) или **маска по началу имени** с `.*` на конце:
`ru.*` исключает все установленные приложения, чьё имя пакета начинается с `ru.` (точка важна: `ru.*` не заденет
`ruslan.app` и `com.rutube.app`). Маска должна иметь основу минимум из двух символов; записи вроде `*` или `a.*`
отбрасываются, чтобы опечатка не вывела из VPN почти все приложения.

- Имя пакета: `adb shell pm list packages | findstr ключевое_слово` (PowerShell) или `adb shell pm list packages | grep слово`.
- Список действует со следующего подключения. Приложения, которых нет на телефоне, пропускаются.
  Маски применяются к тому, что установлено **в момент подключения**: приложение, поставленное при включённом VPN,
  подхватится после переподключения.
- Пользователь видит в Настройках только количество («Приложения вне VPN: N, задаёт сервис»); имена пакетов в отчёт не попадают.
- Нужно разрешение `QUERY_ALL_PACKAGES` (уже в манифесте): с Android 11 без него система скрывает чужие пакеты, и исключение не сработает.
  Для публикации в Google Play оно требует отдельного обоснования; для раздачи APK напрямую ограничений нет.
- Это защита от сравнения IP, а не гарантия необнаружимости: приложение может, например, видеть интерфейс `tun0` или список установленных VPN-клиентов.
  Как отличить: если после исключения предупреждение исчезло — приложение сравнивало IP; если осталось — оно проверяет что-то иное,
  и на уровне VPN-приложения это не исправить.
- Страницы, открытые приложением во внешнем браузере или «Custom Tabs» (Chrome), загружает уже сам браузер — он не исключён и идёт через VPN.
  Страницы во встроенном WebView принадлежат самому приложению и идут напрямую.

### IPv6

У VPN нет IPv6-адреса и маршрута, поэтому Android **блокирует** IPv6 для приложений внутри VPN (они откатываются на IPv4);
утечки IPv6 нет. Приложения из `bypass_apps` ходят по своей сети как обычно, включая IPv6.
